# Bounded SQA smoke compositions

The earlier controlled configured-provider qualification recorded seven
passing controls and 23 budget-closed controls. Reducing the repeated brief
did not improve that coverage. This phase reduces separate model dispatches
during the six technical WEB checks while preserving their evidence contracts.

`run_sqa_smoke_workflow` exposes two fixed configured-provider SQA groups:

- `presentation` collects diagnostics, samples real keyboard/semantic behavior
  and samples responsive viewports. Review those facts, then explicitly record
  WEB-001, WEB-004, WEB-005 and WEB-006 in one control batch.
- `interaction` verifies up to four observed same-origin link names and tests
  local form validation with browser HTTP requests isolated. Review the facts,
  then explicitly record WEB-002 and WEB-003 in one control batch.

The composition invokes the existing SDK executor for every child. Its normal
permission gate, browser policy, workflow checkpoint, reserved closeout limits
and hard budgets run separately. Each child must be durably marked done or
failed before the next dispatch. Navigation/form receipts are saved before the
outer workflow returns, so an immediate control batch has matching host proof.
The outer call does not discount the browser actions it contains.

There is no predicted status input or automatic pass. Actual failures,
unavailable forms, unverified navigation and partial results remain visible to
the model and deterministic control evaluator. A child failure, cancellation,
missing receipt or persistence error stops later work. Async ownership prevents
another tool call or control write from interleaving with the composition.
Closed assessments and reviewer-owned drafts cannot restart. Repeating an
already attempted smoke group is refused; recovery inspects saved activities
and uses only missing individual capabilities where safe.

Native qualified SQA retains `mode_run_workflow`, its discovery/feature plan,
matching immutable receipts and Opus/JEV role boundaries. The new tool is not
registered for that path, Founder or QA. The configured-provider path still
uses the native SDK and the existing atomic control recorder. No dependency,
provider profile, catalog contract, execution budget or assurance gate changes.

The combined source preserves member commit `77c58cc`: native Enter activation
avoids Firefox pointer interruptions during form validation. Its integration
check verifies trusted invalid/submit events with the existing HTTP isolation.

Regression coverage exercises per-child budget checks, cancellation, failure,
missing persistence receipts, dispatch ownership, scope/closed-run boundaries,
and actual configured-provider SDK compositions in Chromium, Firefox and WebKit
without model calls. Each browser fixture saves five child checks through two
outer workflow calls, records technical results in existing batches and keeps
unsupported assurance controls blocked. The caller-data guard also includes
these fixtures. Live comparison and exact-commit release proofs are recorded
separately in the local qualification handoff and GitHub Actions.

The previous seven-pass/23-blocked result is a comparison baseline, not a
promise of more passes on a fixture without performance, security or reviewer
artifacts. Test at the same limits and report measured usage, real evidence
gaps and honest blockers. Studio scope remains export-only.
